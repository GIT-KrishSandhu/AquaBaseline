# AquaBaseline: Smart Water Monitoring That Learns What "Normal" Looks Like

> **1M1B Capstone Project:** Green Skills and Applied AI for Climate Action  
> **Author:** Krish Sandhu (krishsandhu21@gmail.com)  
> **Institution:** KIET Group of Institutions, Uttar Pradesh, India  
> **Prototype Status:** Simulated-Data Prototype · Assumed Baselines Disclosed

AquaBaseline is an AI-powered smart water monitoring web application built with **React 18 + Vite** and **FastAPI + Scikit-Learn**. It replaces rigid campus-wide water thresholds by training localized, hour-aware **Isolation Forest** anomaly detection models that learn each building's individual diurnal rhythm.

---

## Quick Start (5 Commands to Run)

AquaBaseline runs entirely locally without paid cloud services, external databases, or API keys.

```bash
# 1. Navigate to the project root
cd aquabaseline

# 2. Setup dependencies (installs Python backend virtualenv & frontend node modules)
npm run setup

# 3. Start development servers (FastAPI on 8000 + Vite on 5173)
npm run dev

# 4. Open in browser:
# http://localhost:5173

# 5. Run automated unit & integration tests
npm run test
```

## Application Map (10 Pages)

1. **Home (`/`):** Hero with water-ripple visualization, headline stats (276 L/day, 42 vs 30 L/day, 0/60 caught by daily rule), and 4-step engineering strip.
2. **Story (`/story`):** The authentic 6-part student journey from problem discovery to campus scaling with a sticky navigation progress rail.
3. **Research (`/research`):** 3 interactive Recharts analyzing 500 country-year records, 4 statistical insight cards, and raw data toggles.
4. **Dashboard (`/dashboard`):** Real-time hourly waveforms with shaded 10th-90th percentile normal bands, KPI deltas, anomaly dots, and 7-day animated replay.
5. **Scenario Lab (`/lab`):** Interactive fault injection (night leaks, tank overflows, stuck meters, data gaps, holidays) comparing AI detection with fixed daily rules.
6. **Alerts (`/alerts`):** Actionable maintenance inbox with plain-language explanations, sensitivity slider, and plumber feedback loop.
7. **Data Quality (`/data-quality`):** Drag-and-drop CSV auditor evaluating IQR outliers, single-year jumps, and the >2B implied population sanity rule.
8. **Impact (`/impact`):** Six ESG metrics table (live vs assumed), interactive campus savings calculator (~50M L/yr), roadmap, and 95%/70% scale-up gate.
9. **Validation (`/validation`):** Empirical 20-seed simulation findings (80-85% leak recall, 1.2-2.5% false alert days), ablation study, sensitivity matrices, and honest weaknesses.
10. **About (`/about`):** Author profile, 1M1B program credentials, ethical AI tools disclosure, and student learning takeaways.

## Ethical Honesty & Academic Provenance

1. **Simulated Data:** All 15-minute meter readings and buildings (Hostel Block A, Canteen, Academic Block B) are generated by a validated statistical simulator.
2. **Assumed Baselines:** Per-capita consumption (276 L/day), leak losses (12%), campus size (5,000), and water targets (10% cut) are planning assumptions.
3. **Synthetic Dataset Caveat:** Public Kaggle data analyzed on the Research page appears synthetic (as revealed by the implied 5-billion population check). Findings describe patterns in the dataset.
4. **AI Assistants Disclosed:** Claude was used for assignment planning and drafting; Google Antigravity was used for autonomous full-stack engineering and verification.
